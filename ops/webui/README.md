# Локальный WebUI / auth stack

В каталоге находятся compose-шаблон, шаблон клиентской конфигурации и SNB
nginx ACL, использовавшиеся в локальной установке. Это не автономный пакет:
образа ANet публикуются upstream, а рабочая база и секреты находятся вне Git.

## Подготовка

1. Перенесите сюда `.env.example` как `.env` и замените каждый placeholder
   отдельным случайным секретом. Значения из примера запускать нельзя.
2. Сверьте IP интерфейса SNB, ACL источника, compose bind-адреса и tunnel units
   с текущей сетевой схемой.
3. Перед запуском существующей установки выясните имя Compose project и тома
   PostgreSQL. Не создавайте второй стек поверх действующей базы и не удаляйте
   тома.
4. Проверьте образы и их версии/дайджесты. `latest` оставлен как отражение
   прежней конфигурации; для управляемых обновлений закрепляйте проверенный
   тег или digest.

`nginx-snb-proxy.conf` ограничивает доступ адресом `10.32.5.120/32`. Если
адрес клиента или интерфейс прокси изменился, сначала проверьте фактический
источник, который видит nginx; не расширяйте ACL до `0.0.0.0/0`.

Шаблон `client_template.toml` содержит маркеры, которые auth backend заполняет
при выдаче пользовательского конфига. Не заменяйте их реальными ключами и не
сохраняйте скачанные профили в репозитории.
