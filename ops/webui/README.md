# Локальный WebUI / auth stack

В каталоге находятся compose-шаблон, шаблон клиентской конфигурации и SNB
nginx ACL, использовавшиеся в локальной установке. Это не автономный пакет:
образа ANet публикуются upstream, а рабочая база и секреты находятся вне Git.

## Подготовка

1. Перенесите сюда `.env.example` как `.env` и замените каждый placeholder
   отдельным случайным секретом. Значения из примера запускать нельзя.
2. Сверьте IP интерфейса SNB, ACL источника, compose bind-адреса и tunnel units
   с текущей сетевой схемой.
3. Перед запуском существующей установки выясните имя Compose project и тома
   PostgreSQL. Не создавайте второй стек поверх действующей базы и не удаляйте
   тома.
4. Проверьте образы и их версии/дайджесты. `latest` оставлен как отражение
   прежней конфигурации; для управляемых обновлений закрепляйте проверенный
   тег или digest.

## Отправка профиля через Telegram

Пошаговое руководство для администратора: [отправка конфигурации клиенту через
Telegram](telegram-client-delivery.ru.md).

Auth backend хранит введённый в панели токен бота в зашифрованном виде в базе.
Для обратной совместимости он использует `TELEGRAM_BOT_TOKEN` из локального
`.env`, если токен в панели не сохранён. Публичные URL остаются в `.env`:

- `TELEGRAM_BOT_TOKEN` — необязательный резервный токен отдельного бота. Не
  добавляйте его в Git, клиентские конфиги или сообщения.
- `ANET_PANEL_PUBLIC_URL` — внешний HTTPS-адрес панели без завершающего `/`.
- `ANET_CLIENT_DOWNLOAD_URL` — HTTPS-ссылка на приложение, отправляемая клиенту
  через Telegram. Для Android используется стабильное имя APK в публичном
репозитории ANet: `https://github.com/igor04091968/anet-vpn/releases/latest/download/ANet-Android9-10.apk`.
  При выпуске новой версии прикладывайте APK под тем же именем к latest-релизу.
- `HTTPS_PROXY` — необязательный proxy, доступный из контейнера `anet-auth`.
  `127.0.0.1` внутри контейнера указывает на сам контейнер, а не на хост.

Пример переменных находится в `.env.example`; после изменения `.env` обновите
только backend: `docker compose up -d --no-deps anet-auth`.

В панели откройте профиль клиента, укажите его числовой Telegram chat ID и
сохраните. Клиент должен открыть бота и нажать **Start**: бот не может начать
личную переписку первым. Кнопка отправки доставляет ссылку на конфиг клиента и
ссылку на релиз. Ссылка на конфиг открывает доступ к чувствительным данным
профиля, поэтому перед отправкой проверьте chat ID получателя. При утечке ссылки
перевыпустите ключи клиента; при утечке bot token замените его через BotFather,
обновите локальный `.env` и перезапустите `anet-auth`.

`nginx-snb-proxy.conf` ограничивает доступ адресом `10.32.5.120/32`. Если
адрес клиента или интерфейс прокси изменился, сначала проверьте фактический
источник, который видит nginx; не расширяйте ACL до `0.0.0.0/0`.

Шаблон `client_template.toml` содержит маркеры, которые auth backend заполняет
при выдаче пользовательского конфига. Не заменяйте их реальными ключами и не
сохраняйте скачанные профили в репозитории.
