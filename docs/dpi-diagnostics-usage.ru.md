# Диагностика соединений ANet

Дата: 05.10.2026. Реализация: Rust в `anet-client-core/src/diagnostics.rs`, адаптер uTLS в `tools/dpi-helper`, JNI в `anet-mobile/src/diagnostics.rs`, интерфейс в исходниках `/mnt/usb_hdd1/Projects/anet-android`.

## Что проверяется

| Проверка | Быстрая | Расширенная | Что означает успех |
|---|---|---|---|
| DNS настроенного сервера | Да | Да | Получены адреса в выбранной сети |
| TCP для SSH, VNC, WS, AHTTP | Да | Да | Установлено соединение с одним из адресов |
| TLS для WSS/HTTPS | Да | Да | Завершён диагностический handshake rustls |
| uTLS: Chrome, Firefox, Android | Нет | Да | Прошёл handshake выбранного отпечатка |
| Четыре TLS-подключения | Нет | При разрешении политики N | Завершились четыре нативные TLS-попытки |
| Передача 64 КБ | Нет | CLI, при заданном HTTPS echo endpoint | Сервер вернул ровно отправленные случайные байты |
| Реальный QUIC/GOST и аутентификация ANet | Обычное подключение VPN | Обычное подключение VPN | Рабочая сессия ANet |

Для QUIC диагностические TCP-проверки не запускаются. Отправка UDP-пакета сама по себе не подтверждает доступность сервера. Отдельная диагностическая аутентификация с пользовательским ключом не выполняется: повторный вход может вытеснить рабочую сессию на другом устройстве.

Проверка rustls имеет собственный ClientHello. Поле `matches_transport_clienthello=false` запрещает трактовать её как точную копию WSS/AHTTP. Сертификатная цепочка и имя сертификата в диагностических TLS-проверках не проверяются; отчёт явно содержит `certificate_validation=not_checked`. Это не проверка доверия серверу и не замена проверок рабочего транспорта.

Результаты `inconclusive` означают недостаточность данных: причиной могут быть занятый бюджет N, таймаут, отказ сервера, маршрутизация или ограничение сети. Вывод «ТСПУ блокирует» автоматически не делается. Браузерный отпечаток в отчёте не меняет отпечаток рабочего ANet.

## Ограничения запуска

- Диагностика запускается вручную. Подбор применяется отдельной кнопкой с предварительным просмотром; работающая сессия не меняется.
- До 16 endpoint из выбранного набора; до 8 ответов DNS и до 4 попыток адресов для TCP.
- Обычный таймаут операции — 5 секунд, допустимый диапазон — 100–15000 мс.
- Бюджет продолжительности: 60 секунд для быстрой и 180 секунд для расширенной проверки. Отмена закрывает диагностические сокеты. Завершение отменённой операции Go ожидается до освобождения её слота.
- Лимит N и интервал начала подключений общие с текущим экземпляром ANet. Занятые рабочим VPN слоты не отбираются. При их нехватке проверка завершается с недостаточностью данных.
- Параллельный тест пропускается при работающем/подключающемся клиенте, N от 1 до 3 или ненулевом интервале подключений. N=0 означает отсутствие ограничения.
- Четыре нативные попытки не являются точной реализацией upstream Siberian: в отчёте `upstream_siberian_equivalent=false`.
- Бюджет применяется к сокетам транспортов ANet и диагностики. DNS системного резолвера и существующий механизм обновления приложения — отдельные операции.
- Расширенный режим запускается явно и может вызвать временное ограничение со стороны сети.

## Android

Тестовый вариант приложения имеет applicationId `org.alco.anet.diagnostics`, подпись debug и суффикс версии `-diagnostics`. Он устанавливается рядом с рабочим приложением. Рабочий APK обновлять им не следует.

1. Установить тестовый APK и импортировать обычный профиль ANet. Ключи остаются в приложении, диагностическому Go-компоненту не передаются.
2. При активном VPN другого приложения сначала отключить его вручную: тестовый процесс не владеет его VpnService и не может гарантировать защиту своих сокетов. Собственный работающий VPN тестового приложения поддерживается. Открыть «Диагностика» в панели статистики. Начать с «Быстрая».
3. Проверить результаты DNS/TCP/TLS. Для QUIC ожидается отметка о необходимости обычного подключения.
4. При необходимости выбрать «Расширенная». Если задан N=1 или N=2, тест четырёх соединений будет пропущен; менять N ради него автоматически приложение не будет.
5. Нажать «Поделиться JSON» и сохранить отчёт. Ключи, имена профилей, пути и query-параметры DSN в отчёт не включаются. Адреса серверов и идентификатор физической сети присутствуют.
6. Проверить выбранный транспорт обычным подключением ANet. Только оно подтверждает аутентификацию и работу туннеля.

На Android DNS выполняется через выбранный `Network.getAllByName`. TCP-сокет перед подключением защищается через действующий ANet VpnService и привязывается к тому же физическому Network. Нужна физическая сеть с INTERNET и NOT_VPN; активная и подтверждённая Android сеть имеет приоритет. Отсутствие VALIDATED не запрещает диагностику: системная проверка доступа сама может быть недоступна в исследуемой сети. При недоступности привязки проверка не использует туннель как запасной маршрут.

Во время проверки можно отменить её. При начале нового VPN-подключения JNI сначала отменяет и завершает диагностику, затем создаёт новый клиент; это сохраняет бюджет при смене экземпляра. Доступна одна диагностическая задача одновременно. Переключение Wi-Fi/мобильной сети требует нового запуска: отчёт относится к сети, выбранной при старте.

Удаление тестового приложения является откатом испытания. Сервисы ноутбука, рабочие серверы и маршруты этой сборкой не изменяются.

## Linux CLI

Диагностика запускается до проверки root, создания TUN и маршрутов:

```sh
./anet-client --cfg /path/client.toml --diagnose --diagnostics-json /path/report.json

./anet-client --cfg /path/client.toml --diagnose-extended \
  --dpi-helper /absolute/trusted/path/libanet_dpi.so \
  --diagnostics-json /path/report-extended.json
```

Путь библиотеки — доверенный локальный файл. CLI загружает код из неё; библиотека должна поставляться вместе с клиентом. Go-библиотека остаётся загруженной до завершения процесса.

Передача 64 КБ требует отдельного HTTPS endpoint, возвращающего HTTP 200 и точную копию тела POST:

```sh
./anet-client --cfg /path/client.toml --diagnose-extended \
  --dpi-helper /absolute/trusted/path/libanet_dpi.so \
  --diagnostics-echo-endpoint https://control.example.org/echo
```

Не задавать вместо echo endpoint административную форму или обычный путь сервера. Проверка отправляет только случайные данные; ответ HTML, редирект или произвольное «OK» не подтверждают передачу.

## Сборка и лицензии

Go >=1.24; проверено локальным Go 1.25.4. uTLS закреплён на v1.8.2. Таблица профилей адаптирована из dpi-checkers `bb38d7aad0edfffe6d6304f469af48fe8df7c457`. Исходный TUI, сканирование подсетей, загрузка баз и автообновление upstream не включены.

```sh
cd tools/dpi-helper
go build -buildmode=c-shared -o dist/libanet_dpi.so .
./build-android.sh
```

Затем собрать `anet-mobile` для arm64-v8a и armeabi-v7a через cargo-ndk, сохранить предыдущие JNI-библиотеки, скопировать новые `libanet_mobile.so` и `libanet_dpi.so` в соответствующие `app/src/main/jniLibs/`, выполнить `./gradlew :app:assembleDebug`. APK должен содержать оба компонента для обеих ABI. Уведомления и лицензии входят в `assets/dpi-helper`.

## Проверка реализации

На локальных серверах проверяются: TLS, соблюдение N, отмена и освобождение слотов, отсутствие query-параметров DSN в JSON, отсутствие фиктивного TCP-успеха для QUIC, C ABI и сохранение исходного FD, корректная отмена Go, полный echo roundtrip и отбрасывание обычного HTTP-ответа. Проверки Go выполняются с `-race`.

Сборка APK подтверждает компиляцию и упаковку. Работа JNI на телефоне, реальное поведение операторских сетей и конкретные ограничения ТСПУ требуют испытания на устройстве. Проверки производственных серверов в ходе разработки не запускались.

## Подбор настроек в Android (1.0.3)

После завершения диагностики нажать «Подобрать настройки», выбрать сервер и нажать «Применить и подключить». Подбор использует только endpoint выбранной группы импортированного профиля. Прошедшие TCP/TLS кандидаты ставятся выше непроверенных, но TLS не доказывает доступность ANet. QUIC остаётся вариантом для проверки обычным подключением.

Предел внешних соединений — 1, либо 2 для группы с AHTTP; более строгий пользовательский N сохраняется. При N=1 AHTTP исключается из подбора: ему нужны отдельные соединения для приёма и отправки. Интервал новых попыток — не менее 500 мс, при неудачном параллельном TLS-тесте — 1000 мс. Параллельность запросов AHTTP ограничивается двумя. Это осторожный исходный выбор для испытаний, а не универсальный способ обхода блокировок.

Исходный профиль, ключи, адреса, криптография и маршруты не переписываются. Для запуска создаётся временная копия с новым порядком endpoint и ограничениями. Резервные endpoint той же группы сохраняются. MTU принимается через существующий ответ авторизованного сервера; транспорт и фактически использованное шифрование отражаются в статусе. Нового протокола согласования серверных возможностей пока нет.

Для сохранения успешного подбора требуется авторизация, отправленные пакеты и приём не менее 64 КиБ через этот туннель в течение двух минут. После подключения открыть сайт или другой разрешённый ресурс с данными. Сам диагностический TLS и одна авторизация успехом передачи данных не считаются. Это проверка факта передачи, не гарантия качества всех сайтов или устойчивости к ТСПУ.

Сохраняется один результат для точного профиля, группы и физической сети Android; срок — 30 минут с применения, сам отчёт также годен 30 минут с начала диагностики. Смена сети, профиля или группы отменяет применение. Смена идентификатора Network после перезапуска также требует нового подбора. Никакого автоматического прерывания работающего VPN при истечении срока нет.

Откат: остановить VPN, открыть «Диагностика» → «Исходные настройки», подключиться снова. Импортированный профиль остаётся исходным. Проверка на реальном Android 10 ещё требуется; сборка и тесты не заменяют её.
