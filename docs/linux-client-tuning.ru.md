# Linux-клиент ANet 1.0.3: диагностика и подбор

Сборка для x86_64: консольный `anet-client`, расширенная библиотека `libanet_dpi.so`, лицензии. Это экспериментальный релиз. Новый подбор пока не добавлен в графический Linux-клиент.

## По шагам

Диагностика использует системные DNS и маршруты. Если уже работает VPN, часть измерений может проходить через него. Отчёт учитывает состояние других туннелей; после их остановки нужно повторить диагностику. В отличие от Android, привязки диагностических сокетов к физическому Network нет. Программа не отключает существующие VPN и не меняет маршруты в режиме диагностики, просмотра или экспорта.

```sh
./anet-client --version
./anet-client --cfg client.toml --diagnose --diagnostics-json report.json
# Необязательно, только для отдельного расширенного испытания:
./anet-client --cfg client.toml --diagnose-extended \
  --dpi-helper "$PWD/libanet_dpi.so" --diagnostics-json report-extended.json
```

Подбор из свежего отчёта:

```sh
./anet-client --cfg client.toml --tuning-report report.json
```

Если профиль содержит группы, добавить `--group ID` с точным `group_id` (либо `group_name`, если id отсутствует). Отчёт проверяет исходный профиль, время и состояние сети. Старый Android-отчёт или предыдущий Linux-отчёт с `system_routes` не подойдёт. Показанный `index` — индекс endpoint в исходном TOML, а не его место в отсортированном списке.

Сохранить выбранный вариант отдельным файлом (здесь `0` — пример; взять нужный index из рекомендации):

```sh
./anet-client --cfg client.toml --tuning-report report.json \
  --tuning-candidate 0 --tuning-output client-tuned.toml
```

Исходный профиль не переписывается. Копия создаётся атомарно с правами 0600. Перезапись исходного файла, включая его symlink-алиас, запрещена. Копия содержит ключи, поэтому её нельзя отправлять в публичный Git/чат. Это обычный экспортированный конфиг: его последующий ручной запуск через `--cfg` не проверяет срок отчёта и привязку к сети. Для проверки срока и сети использовать режим ниже.

## Подключение и подтверждённый кэш

Только после ручной остановки других VPN/туннелей и повторной диагностики:

```sh
sudo ./anet-client --cfg client.toml --tuning-report report.json \
  --tuning-candidate 0 --tuning-connect --tuning-cache tuning-cache.json
```

При активном другом туннеле этот режим отказывает до создания TUN и изменения маршрутов. Это защищает действующие OpenVPN/WireGuard/ANet подключения; программа не останавливает их автоматически. Параллельные новые запуски защищены lock-файлом `/run/anet-client-tuning.lock`; проверка действующих туннелей повторяется после получения lock. Обычный запуск старым способом без `--tuning-connect` сохраняет прежнее поведение.

Выбор и ограничения применяются к временной копии конфигурации. Ключи, серверные адреса, endpoint-алгоритмы шифрования и маршруты сохраняются; MTU приходит из авторизованного ответа сервера. N не более 1, либо 2 для группы с AHTTP, более строгий пользовательский N сохраняется. При N=1 AHTTP исключён. Интервал попыток не менее 500 мс, при неудачном параллельном TLS-тесте — 1000 мс. Диагностический uTLS-отпечаток не становится настройкой рабочего TLS.

Открыть разрешённый сайт/ресурс с данными. Для кэша требуются авторизация, TX>0 и RX>=64 КиБ в пределах 120 секунд с начала запуска. Если сработал резервный сервер той же группы, сохраняется фактически использованный endpoint. Это проверка факта обмена, не проверка загрузки каждого сайта или обхода ТСПУ.

```sh
# Использовать подтверждённый кэш, если профиль/группа/сеть и срок совпадают:
sudo ./anet-client --cfg client.toml --tuning-connect --tuning-cache tuning-cache.json
# Сбросить кэш, не создавая VPN:
sudo ./anet-client --reset-tuning-cache tuning-cache.json
```

Срок кэша — до 30 минут; исходный отчёт также годен 30 минут с начала диагностики. Идентификатор сети учитывает физические адреса/шлюзы, NetworkManager UUID, другие активные туннели, boot ID и сетевое пространство имён. Собственный вновь созданный TUN исключён из отпечатка. Изменение сети не перестраивает работающий туннель автоматически. Неподходящий кэш отклоняется; нужно повторить диагностику и выбрать вариант явно.

Кэш, созданный через sudo, имеет владельца root и права 0600; читать/сбрасывать его также через sudo. Без `--tuning-cache` подключение не создаёт постоянных настроек.

## Откат и границы проверки

Остановить новый клиент Ctrl+C, сбросить кэш и запускать исходный `client.toml`. Рабочий сервис ноутбука и его бинарник этим архивом не заменяются. Не запускать вторую сессию с тем же клиентским ключом на другом устройстве: она может вытеснить действующую сессию.

Зависимости Linux: `iproute2`, libc/системные библиотеки из `ldd anet-client`; NetworkManager опционален. Проверка текущей сборки: core/CLI тесты, реальный CLI на локальном QUIC-профиле без авторизации/UDP-сессии, экспорт 0600, отклонение старого/чужого отчёта, запрет перезаписи исходника и отказ запуска при действующих туннелях. Реальное VPN-подключение и запись подтверждённого кэша на ноуте не испытывались, чтобы сохранить действующие маршруты. Архив не содержит клиентских профилей и ключей.
