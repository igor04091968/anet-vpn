## Вывод

Добавить диагностический модуль можно. Его результаты должны помогать выбирать доступный сервер, транспорт и параметры клиента. Успешная проверка обычного TLS сама по себе не подтверждает работоспособность ANet, а отказ соединения не доказывает вмешательство ТСПУ.

Для первой версии рекомендуется Rust-модуль диагностики наших endpoint с использованием реальных транспортов клиента. Проверки dpi-ch подключать как дополнительный инструмент через адаптированное Go-ядро с машинным интерфейсом. Такое разделение сохраняет возможность проверить именно тот сетевой обмен, который будет использовать ANet.

## Что есть в upstream

Документация описывает проверки DNS, доступности, ограничения передачи данных, ограничения по подсетям и параллельным TLS-подключениям, экспорт JSON/YAML и сборки для Android через Termux. [Документация](https://github.com/hyperion-cs/dpi-checkers/blob/bb38d7aad0edfffe6d6304f469af48fe8df7c457/ru/dpi-ch/docs/README.md).

Исходный код написан на Go. В проверенной версии `--all` запускает проверки с сохранением результата, но старт по-прежнему проходит через TUI; `--ui web` пока ведёт к заглушке. Для встраивания нужен собственный запуск проверок без терминала и обмен результатами. Android-сборка для Termux не является готовой библиотекой для APK. [main.go](https://github.com/hyperion-cs/dpi-checkers/blob/bb38d7aad0edfffe6d6304f469af48fe8df7c457/ru/dpi-ch/main.go), [TUI](https://github.com/hyperion-cs/dpi-checkers/blob/bb38d7aad0edfffe6d6304f469af48fe8df7c457/ru/dpi-ch/tui/tui.go).

В конфигурации по умолчанию webhost использует восемь работников, а проверка Siberian — четыре параллельных соединения. Запуск штатного набора может расходиться с установленным пользователем пределом N. В продукте необходимо заменить состав целей и режим запуска. [Конфигурация](https://github.com/hyperion-cs/dpi-checkers/blob/bb38d7aad0edfffe6d6304f469af48fe8df7c457/ru/dpi-ch/config/default.yaml).

uTLS позволяет тестировать заданные ClientHello-профили. Наши TLS-транспорты используют Rust/rustls; их отпечатки могут отличаться. Из успешного теста Firefox или Chrome нельзя автоматически вывести успешность ANet. Изменение User-Agent не меняет ClientHello. [TLS-код dpi-ch](https://github.com/hyperion-cs/dpi-checkers/blob/bb38d7aad0edfffe6d6304f469af48fe8df7c457/ru/dpi-ch/inetutil/tls.go).

## Предлагаемая архитектура

```text
Кнопка «Проверить сеть» / ошибка подключения / смена сети
  → координатор Rust: бюджет соединений, время, отмена
  → собственные проверки ANet + адаптер проверок dpi-ch
  → структурированный отчёт с наблюдениями и степенью уверенности
  → выбор кандидата из разрешённых серверов и транспортов
  → проверка реального ANet-соединения
  → подключение и сохранение успешного варианта для этой сети
```

Предлагаемые точки интеграции:

- `anet-client-core/src/diagnostics/`: проверки, результаты, выбор кандидата;
- `connection_limits.rs`: единый бюджет диагностических и рабочих соединений;
- `events.rs`: события прогресса и готового отчёта;
- `client.rs`: проверка кандидата и выбор следующего транспорта;
- `anet-mobile`: интерфейс запуска, отмены и JSON-результата;
- Android: экран диагностики и работа с конкретной физической сетью;
- отдельный Go-адаптер: вызов выбранных пакетов checkers без TUI, автообновления и полного штатного обхода провайдеров.

Это план новых компонентов. Указанные API и экран в клиенте пока отсутствуют.

## Режимы работы

### Быстрая проверка

Проверять серверы из пользовательского профиля и небольшой согласованный набор контрольных адресов. Предварительный бюджет — до 30 секунд и двух одновременных проверок, дополнительно ограниченных общим N клиента. Точные бюджеты уточнить на мобильных сетях.

Проверить DNS, достижимость endpoint, TCP/TLS там, где они действительно используются, и обмен реальным протоколом ANet. QUIC/UDP, SSH, VNC и внешний GOST-обмен проверять соответствующими транспортами ANet: общий TCP/TLS-тест их не заменяет.

Если VPN уже работает, использовать сведения здоровья существующей сессии и не выполнять параллельную полноценную авторизацию тем же ключом без проверки поведения сервера. Это может затронуть действующую сессию или её лимит.

### Расширенная проверка

Отдельный пользовательский запуск для тестов параллельных TLS-подключений, передачи объёма данных и сравнения TLS-профилей. Такой тест может вызвать временный отказ доступа; он не должен автоматически запускаться на рабочем endpoint при каждом переподключении.

Если N=2, нельзя незаметно открывать четыре диагностических подключения. Отметить тест как пропущенный из-за бюджета. Для испытания большего числа каналов пользователь выбирает отдельный режим с явно показанным временным бюджетом. До его завершения автоматические попытки подключения к проверяемой цели приостановить.

Не использовать одну только настройку количества работников как гарантию N: одна проверка способна открывать несколько сокетов. Go-адаптер должен согласовывать открытия и закрытия с координатором Rust или проводить диагностику в отдельной фазе с проверенным собственным общим ограничителем.

## Как использовать результаты

| Наблюдение | Действие клиента |
|---|---|
| DNS даёт неверные или недоступные адреса | Проверить альтернативное разрешение из разрешённых настроек; не отключать проверку подлинности сервера |
| TCP устанавливается, TLS зависает | Сопоставить с контрольной целью, TLS-ошибками и серверной доступностью; проверить другой разрешённый транспорт |
| Передача начинается и затем останавливается | Проверить более длительный обмен ANet и альтернативный endpoint; отличать фильтрацию от потерь и перегрузки |
| Малое число попыток проходит, параллельные не проходят | Рекомендовать уменьшение N и увеличение интервала; результат относится к измеренным условиям |
| Транспорт ANet проходит аутентификацию и обмен | Сохранить его как успешный кандидат для текущей сети |
| Результат неоднозначен | Показать «недостаточно данных», сохранить ручной выбор и ограничить повторы |

Не добавлять автоматический выбор browser fingerprint, пока соответствующий механизм отсутствует в рабочем TLS-транспорте. Профиль uTLS диагностического инструмента не переносится одним параметром в rustls.

Кэш результатов привязать к типу и идентификатору сети и проверенному endpoint; при смене Wi-Fi/мобильной сети перепроверять. Не переподключать работающий туннель по единственному случайному таймауту. Записывать наблюдаемые этапы, задержки, число попыток, профиль TLS, факт прямой проверки/проверки через VPN и время измерения.

## Android

В APK предпочтителен библиотечный интерфейс Go через подготовленную обёртку JNI/C ABI, если испытания размера, памяти и жизненного цикла покажут приемлемый результат. Второй вариант — портирование выбранных простых проверок в Rust; перенос поведения uTLS потребует отдельного решения.

Для измерения сети оператора диагностический трафик должен идти через выбранную физическую сеть. На Android для сокетов предусмотрены `VpnService.protect()` и привязка к `Network`; проверять успешность операции. Не останавливать рабочий VPN ради диагностики. [Android API](https://developer.android.com/reference/android/net/VpnService#protect(int)).

В просмотренной Android-копии ANet обычный режим исключает собственный пакет из VPN, а режим списка приложений формирует отдельные разрешения. Это нужно учесть при интеграции; нельзя считать поведение одинаковым во всех режимах или всех версиях APK. Для desktop также нужен явный выбор пути проверки, без изменения default route.

## Поставка и лицензия

Upstream распространяется под Apache-2.0. При включении его кода или бинарной библиотеки сохранить лицензию и требуемые уведомления, обозначить изменения; отдельно учесть лицензии зависимостей. [Лицензия](https://github.com/hyperion-cs/dpi-checkers/blob/bb38d7aad0edfffe6d6304f469af48fe8df7c457/LICENSE).

Закрепить проверенную ревизию и поставлять компонент с приложением. Самообновление dpi-ch и загрузку больших баз отключить в обычном режиме. Не передавать диагностическому компоненту ключи ANet и не включать их в JSON-отчёт. Привилегированный доступ для базовых сокетных проверок не предполагается; фактические разрешения проверить на целевых Android-версиях.

## Этапы и приёмка

1. Реализовать модель отчёта и последовательную проверку реальных endpoint в Rust с общим лимитом.
2. Добавить экран диагностики и Android-выбор физической сети; проверить, что измерения не идут через сам туннель.
3. Подготовить Go-адаптер выбранных dpi-ch проверок, отмену и ограниченный машинный интерфейс.
4. Добавить расширенные тесты отдельным режимом.
5. Подключить выбор кандидатов и кэш после проверки на реальных операторах.

Обязательные проверки: N соблюдается при совместной работе транспорта и диагностики; отмена освобождает сокеты; отчёт не содержит ключей; смена сети сбрасывает устаревшее решение; DNS/серверная ошибка не объявляется доказанной блокировкой; работающая сессия не прерывается; неудачный автоматический выбор возвращается к прежнему рабочему кандидату.
